# Sandbox: главное меню и состояние карты через SignalR

При запуске появляются три кнопки: **Create game**, **Connect**, **Exit**.

- **Create game** загружает `Default_Map` в BoardState и передаёт снимок карты
  через SignalR. Сервер создаёт сессию, сохраняет карту и добавляет создателя
  как первого игрока. После ответа открывается карта с кодом игры.
- **Connect** открывает ввод кода. Введите 6 символов, нажмите Connect или Enter.
  Клиент получает карту сервера и строит изображение из неё, не читая локальные CSV.
- **Exit** закрывает окно. **Main menu** на карте отключает игрока и возвращает меню.
  Escape возвращает меню; из главного меню — закрывает приложение.

Ошибки подключения показываются на экране, окно продолжает работать.
Сетевые обращения имеют таймауты; графические объекты создаются только в Game1.Update.

## Запуск в PowerShell

Нужны .NET SDK 8 или новее, Docker Desktop с Linux containers.
Из корня board-game:

```powershell
docker compose up -d --build
cd Sandbox
dotnet run
```

Или из корня `./start-test.ps1`.
После изменений сервера обязательно пересоберите Docker-образ.

Откройте второй терминал в Sandbox и снова выполните `dotnet run`.
В первом окне выберите Create game, во втором — Connect и введите код.

Адрес и имя игрока задаются при желании перед запуском:

```powershell
$env:GAME_SERVER_URL = 'http://localhost:5285'
$env:GAME_PLAYER_NAME = 'Vagif'
```

Если имя не задано, клиент создаёт уникальное `Player-xxxxxx` для этого окна.
Имена в одной сессии должны отличаться. Старый адрес `ws://localhost:5285`
также принимается и преобразуется в HTTP URL для HubConnection.

Путь к карте можно переопределить через GAME_MAP_DIR. Он нужен только создателю.

Если Windows заблокировала скачанный манифест, из корня выполните:

```powershell
Unblock-File -LiteralPath .\Sandbox\.config\dotnet-tools.json
```

## Серверные методы

Существующие методы CreateSession, JoinSession, LeaveSession, EndTurn сохранены.
В GameHub добавлены:

| Метод | Назначение |
|---|---|
| CreateGame(BoardSnapshot state, string username) | Создание сессии с картой и первым игроком |
| ConnectGame(string code, string username) | Вход и получение карты этой сессии |

Оба возвращают GameConnectionResult с Code и State.
ServerConnection использует Microsoft.AspNetCore.SignalR.Client, маршрут `/gamehub`.
Событие PlayerCountChanged обновляет число игроков на экране.
В этой версии отдельного HTTP API для карты нет.

В Program.cs сохранены SignalR и Serilog; добавлены `/health` и лимит входящего
сообщения 1 МиБ. Это позволяет стартовому скрипту дождаться сервера и передать карту.
Docker собирается из корня репозитория, включая все ProjectReference.

Состояние находится в GameSession.Board и хранится в оперативной памяти.
После выхода последнего игрока сессия удаляется. Перезапуск сервера тоже удаляет игры.

## Что передаётся

BoardSnapshot сохраняет все поля текущего BoardState: гексы и их числа/местность,
регионы, опустынивание, узлы и флаги, племена, требования путей, счётчики,
заблокированные пути и позиции врагов. Для сети словари превращаются в массивы.
После получения создаётся новый BoardState, затем строится геометрия.

Исправлена идентичность недиректированного Path: сравнение по координатам и
одинаковый хеш для обратного направления. Это необходимо для проверки BlockedPaths
при рисовании заново созданных обычных переходов.

Отрисовка обновлённого файла сохранена: обычные пути золотистые, исследовательские —
красноватые, без рамок гексов. Узлы рисуются после всех линий.

Это состояние **карты**, которую сейчас отображает Sandbox. Начальные лагеря,
исследователи, ресурсы игроков и правила игровых действий этим изменением не добавлены.
GameState с фазами/решениями пока не связан с серверной сессией. Старая библиотека
GameClient остаётся в проекте, но Sandbox её не использует.

## Проверка

После запуска контейнера, из корня:

```powershell
dotnet run --project tests/MenuIntegrationTests
```

Тест проверяет восстановление снимка, обратные заблокированные пути, создание,
вход, передачу изменённой карты, счётчик участников, повторный вход, выход и удаление
пустой сессии. Старые Python-тесты предназначены для прежнего WebSocket API;
для этой версии используйте MenuIntegrationTests.

Ручная проверка: создайте игру, временно переименуйте Default_Map и запустите
второе окно. Connect должен отрисовать карту из ответа сервера. Верните имя каталога.

В среде подготовки отсутствуют .NET SDK и Docker. Компиляция C#, запуск контейнера
и визуальная проверка окна не выполнялись. Проверены структура проекта, XML,
Docker-контекст, CSV, целостность архива и сохранение обновлённых методов отрисовки.
